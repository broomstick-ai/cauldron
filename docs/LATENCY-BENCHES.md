# Latency benches

Two `#[ignore]`d benches time a send end to end in two halves: `CAULDRON_ISOLATED=1 cargo test -p shapewire --features server --test auth_gate -- --ignored --nocapture door_request_round_trip` times shapewire's door alone (one websocket request -> response through the chassis to a do-nothing producer; median ceiling 20 ms, `SHAPEWIRE_LAT_*`), and `CAULDRON_ISOLATED=1 cargo test -p threads --test it -- --ignored --nocapture send_round_trip_into_a_held_thread_latency` times a real `threads/{id}/send` into a held thread (append + enqueue, no turn; N >= 250, prints load average, median/p90/p99; median ceiling 25 ms judged only when the 1-minute load sampled after warm-up is <= 20, `THREADS_SEND_LAT_*`). Above that load the threads bench FAILS with `NOT JUDGED` and the numbers unless `THREADS_SEND_LAT_ALLOW_UNJUDGED=1` is set, in which case it passes and prints `NOT JUDGED`; the margin at load ~20 is thin (worst median seen there 21.1 ms vs 25), so a red near the cap means re-run first. Read side by side, the two medians bound the send handler's share of the round trip, but that share is derived, not measured: the benches also differ in auth (the door bench authenticates once, outside the timed loop), request framing and producer. `push_burst_of_50_with_and_without_tcp_nodelay` (same `threads` binary) is an informational A/B of a 50-push burst with and without `TCP_NODELAY`.
